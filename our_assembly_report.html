01

Analysis Methods

  1. Raw PacBio Revio HiFi reads — the identical input NICEM received (confirmed below: read count, total yield, and read-length N50 match exactly for both strains).
  2. De novo assembly with hifiasm v0.25.0-r726, each strain independently.
  3. Haplotig purging with purge_dups v1.2.6, using coverage-anchored manual cutoffs rather than the tool's automatic defaults differs from NICEM — NICEM's report does not apply a purging step to either assembly.
  4. Self-polishing: pbmm2 v26.2.99 (map HiFi reads back to the purged assembly) → bcftools v1.21 mpileup/consensus differs from NICEM — NICEM uses NextPolish v1.4.1 for the same purpose.
  5. Completeness assessment with BUSCO v6.0.0, lineage chlorophyta_odb10 (1,519 BUSCOs) differs from NICEM — NICEM uses the broader eukaryota_odb10 lineage (255 BUSCOs).
  6. Ab initio gene prediction with AUGUSTUS v3.5.0, chlorella species model, on the purged assembly.
  7. Protein-level annotation: DIAMOND blastp (best hit, e-value ≤ 1e-5) against the local UniProtKB/Swiss-Prot database (487,492 sequences) differs from NICEM — NICEM's report uses classic blastx (BLAST 2.6.0+) against the much larger NCBI nr database, then merges GO via OmicsBox/Blast2GO + InterProScan.
  8. GO term cross-reference via the UniProt REST API (batch accession lookup, biological process / molecular function / cellular component fields) for every unique Swiss-Prot hit.
  9. Variant calling (not part of NICEM's report, included here for completeness): bcftools v1.21 + GATK v4.6.2.0, cross-validated in both reference directions, plus pbsv v2.11.0 and Sniffles2 v2.8.0 for structural variants.

05

Notes & known methodological differences

Read honestly, not glossed over

Every “differs from NICEM” tag above is a genuine methods choice, not an error on either side — each is called out explicitly in §01 rather than left implicit. The two that most affect number-for-number comparability: (1) our purge_dups step removes duplicate haplotig content NICEM's unpurged assemblies retain, so raw contig/length totals should not be compared directly — use the purged, final numbers in §02; (2) our GO annotation uses a much smaller, curated database (Swiss-Prot, ~487K sequences) than NICEM's nr (hundreds of millions), which is the primary reason our hit rate (57.5% HS2, 57.6% ALE) reads lower than NICEM's (87.2% ALE, 87.0% HS) — this reflects database coverage, not gene-model quality. One number we checked and could not fully reconcile: NICEM reports Q32–33 median per-read quality; our own seqkit-computed mean base quality for the identical read files comes out at Q23.5–23.7 — likely a different quality-metric definition (median vs. mean, per-read HiFi consensus QV vs. per-base Phred average) rather than a real discrepancy in the underlying data, but flagged here rather than silently reconciled.

Full command-by-command pipeline, every non-default parameter, and the reasoning behind each: report8.html § Methods. Six-point original review + independent-replication cross-check: nicem_comparison.html.
